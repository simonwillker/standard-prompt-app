## 1. 背景与目的

同一个需求，每次用不同写法的 Prompt 去问 AI，得到的输出格式、粒度、质量都不一样，结果无法复用，也无法自动化处理。

本APP的目的：

1. 把"写 Prompt"变成**填表**：用户只需按需求填写固定项目，APP 按统一结构生成标准Prompt。
2. 让同一需求**每次得到相同结构、相同质量的输出**（Output 标准化）。
3. 把好用的 Prompt 沉淀为**可复用的模板**，团队内共享、版本管理。

## 2. 核心思路：输出为什么能稳定

输出的一致性来自以下要素，APP 生成的每一个标准Prompt都强制包含它们：

| # | 要素 | 作用 |
|---|------|------|
| 1 | 角色（Role） | 固定AI的立场与专业视角 |
| 2 | 任务（Task） | 用一句话说明要做什么、目标是什么 |
| 3 | 输入（Input） | 明确输入数据的位置与格式，用分隔符包起来 |
| 4 | 输出格式（Output Format） | 用固定模板/JSON Schema/Markdown 结构规定输出，最关键的一项 |
| 5 | 示例（Few-shot） | 给出 1〜3 组"输入→理想输出"示例 |
| 6 | 约束（Constraints） | 字数、语言、语气、禁止事项 |
| 7 | 信息不足时的处理 | 规定缺信息时是"提问"、"标注未知"还是"按默认值" |
| 8 | 运行参数 | temperature=0、固定模型版本号 |
| 9 | 输出校验 | 按格式校验，不合格自动重试（规定次数） |

## 3. 用户与使用场景

- **主要用户**：需要反复用 AI 处理同类工作的个人或团队成员（不要求懂 Prompt 技巧）。
- **模板管理者**：负责设计、审核、发布模板的人。

典型场景：

1. 用户选择模板「会议纪要整理」→ 粘贴会议记录 → 得到标准Prompt → 复制到任意AI工具使用。
2. 用户没有现成模板 → 用自然语言描述需求 → APP 引导填写各要素 → 生成新模板并保存。
3. （后期）在插件内直接按标准Prompt执行，并自动校验输出格式。

## 4. 功能需求

### 4.1 MVP（第一版必须实现）

| ID | 功能 | 说明 |
|----|------|------|
| F-01 | 需求输入表单 | 按第2章的要素分栏填写；必填项未填不能生成 |
| F-02 | 标准Prompt生成 | 按固定结构（见第5章）拼装，输出纯文本，一键复制 |
| F-03 | 模板保存 | 把填好的表单保存为模板（名称、分类、说明、版本号） |
| F-04 | 模板列表/检索 | 按名称、分类、标签检索；查看、复制、删除 |
| F-05 | 变量占位符 | 模板中支持 `{{变量名}}`，使用时只填变量即可生成 |
| F-06 | 导入/导出 | 模板以 JSON/YAML 文件导入导出，便于用 Git 管理 |
| F-07 | 质量检查 | 生成前检查：是否有输出格式、是否有示例、是否写了缺信息处理，给出提示 |

### 4.2 第二阶段（可选）

| ID | 功能 | 说明 |
|----|------|------|
| F-11 | AI辅助起草 | 用户用一句话描述需求，由AI预填各要素，用户再修改 |
| F-12 | 插件内执行 | 生成Prompt后直接执行，得到结果 |
| F-13 | 输出校验与重试 | 按模板定义的 JSON Schema / 必含章节校验，不合格自动重试，最多N次 |
| F-14 | 一致性测试 | 同一输入运行多次，比较输出差异，给出一致性评分 |
| F-15 | 模板版本对比 | 显示版本间差异，可回滚 |
| F-16 | 多语言 | 生成中文/日文/英文Prompt |

## 5. 标准Prompt结构（输出规范）

APP 生成的 Prompt 一律采用以下结构，章节顺序和标题固定不变：

```
# 角色
你是{{角色}}。

# 任务
{{任务说明}}

# 输入
以下 <input> 标签内是需要处理的内容：
<input>
{{输入内容}}
</input>

# 输出格式
必须严格按照以下格式输出，不要添加格式以外的任何说明：
{{输出模板 或 JSON Schema}}

# 示例
<example>
输入：{{示例输入}}
输出：{{示例输出}}
</example>

# 约束
- {{约束1}}
- {{约束2}}

# 信息不足时
{{处理方式：例如"在对应项填写『不明』，不要推测"}}
```

运行参数（作为模板的附带信息保存，不写进Prompt正文）：

- 模型：固定版本号（例：claude-opus-5-5）
- temperature：0
- 最大重试次数：2

注：作为 Claude 插件运行时，temperature 和模型由宿主工具决定，插件无法强制指定。因此插件形态下的一致性主要靠固定结构、输出格式、示例和输出校验来保证；run 参数用于通过 API 调用时。

## 6. 数据设计（模板）

```yaml
id: meeting-minutes
name: 会议纪要整理
category: 文书
tags: [会议, 纪要]
version: 1.0.0
description: 把会议记录整理成固定格式的纪要
role: 资深行政秘书
task: 把输入的会议记录整理成会议纪要
input_spec: 会议的文字记录（可能有口语、重复）
output_format: |
  ## 会议概要
  - 日期：
  - 参加者：
  ## 决定事项
  1.
  ## 待办事项（负责人 / 期限）
  1.
output_schema: null        # 需要JSON输出时填写 JSON Schema
examples:
  - input: "..."
    output: "..."
constraints:
  - 使用简体中文
  - 不添加原文中没有的信息
missing_info_policy: 原文中没有的项目填写「不明」
variables: [输入内容]
run:
  model: claude-opus-5-5
  temperature: 0
  max_retries: 2
created_at: 2026-10-03
updated_at: 2026-10-03
```

## 7. 交付形态：插件

最终以**插件（Plug-in）**形式交付，装进 AI 工具后即可使用，不需要单独打开一个APP。

### 7.1 目标平台（默认）

- **Claude 插件**（Claude Code / Cowork 通用的插件格式），通过 Git 仓库作为插件市场分发，安装后在对话中直接调用。
- 选择理由：模板是纯文本文件，与插件格式天然契合；安装、更新、团队共享都通过 Git 完成。

### 7.2 插件构成

```
standard-prompt-app/
├── .claude-plugin/
│   ├── plugin.json          # 插件元信息（名称、版本、说明）
│   └── marketplace.json     # 让本仓库可作为插件市场被添加
├── skills/
│   └── standard-prompt/
│       └── SKILL.md         # 核心：按第5章结构生成标准Prompt的规则
├── commands/
│   ├── prompt-new.md        # /prompt-new   新建模板（引导填写各要素）
│   ├── prompt-use.md        # /prompt-use   选择模板、填变量、生成Prompt
│   ├── prompt-list.md       # /prompt-list  模板一览/检索
│   └── prompt-check.md      # /prompt-check 质量检查
├── templates/               # 模板库（YAML，第6章格式）
│   └── meeting-minutes.yaml
└── docs/spec.md
```

### 7.3 使用流程

1. 安装：在 Claude 中添加本仓库为插件市场 → 安装插件。
2. 新建模板：`/prompt-new` → Claude 逐项询问角色、任务、输出格式等 → 保存为 `templates/*.yaml`。
3. 使用模板：`/prompt-use 会议纪要` → 只输入变量 → 输出标准Prompt（或直接按该Prompt执行）。
4. 更新：模板修改后提交到 Git，团队成员更新插件即可同步。

### 7.4 功能与插件的对应

| 功能 | 插件中的实现 |
|------|-------------|
| F-01 需求输入表单 | `/prompt-new` 对话式逐项填写 |
| F-02 Prompt生成 | `standard-prompt` 技能按固定结构拼装 |
| F-03/F-04 保存、一览 | `templates/` 目录 + `/prompt-list` |
| F-05 变量 | `/prompt-use` 时填写 `{{变量}}` |
| F-06 导入导出 | 模板即文件，直接复制或通过 Git |
| F-07 质量检查 | `/prompt-check` |
| F-12/F-13 执行与校验 | 插件内直接执行，按 output_schema 校验，不合格重试 |

## 8. 非功能需求

- **再现性**：同一模板 + 同一变量 → 生成的Prompt文本完全一致（逐字相同）。
- **易用性**：不懂Prompt技巧的人，5分钟内能用模板生成第一个Prompt。
- **可移植性**：模板为纯文本文件（YAML/JSON），可放在 Git 仓库里管理和评审。
- **安全**：API Key 只保存在本地或服务器环境变量中，不写进模板文件。

## 9. 技术方案（建议，待确认）

- 形态：Claude 插件（见第7章）
- 实现：技能（SKILL.md）+ 斜杠命令（Markdown）+ 模板文件（YAML），基本不需要编写程序代码
- 数据：模板存放在插件仓库的 `templates/` 目录，用 Git 做版本管理
- 校验（第二阶段）：如需严格的 JSON Schema 校验，追加一个小脚本或 hook
- 备选：如果需要在 Claude 以外使用（如 VS Code、浏览器扩展），再追加对应形态的插件
